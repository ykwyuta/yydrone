# 将軍・参謀本部

戦闘画面の **司令部** または **F3** で開きます。画面を開いている間は、従来の各種一覧と同じくシミュレーションが一時停止します。マウスとタッチの両方で操作できます。

各陣営に **将軍9人・参謀1人**、両陣営合計20人を用意しています。将軍は3人ずつ3ページで切り替えます。

## 将軍への委任

1. 「指示と予算」で、積極攻勢・全力防御・臨機応変を選びます。
2. 手元資金から100または500ずつ予算を渡します。未使用分は返還できます。
3. 「地域と部隊」で「地図で中心を指定」を押し、地図上で担当地域の中心を指定します。円の半径は28・42・64タイルです。
4. 選択した部隊、または地域内の自軍部隊を委任します。他の将軍の部隊を選んだ場合は所属を移します。飛行中のFPVと巡航ミサイルは委任対象外です。

将軍は地域内の都市・確認済みの敵・自軍戦力・損耗・補給を考慮し、おおむね8秒間隔で命令を見直します。目的地は担当円内に収めます。道路や橋を使う移動経路が円を出る場合はあります。命令を受けた部隊は、指揮官の性格によって攻勢に出る条件や撤退する耐久率が変わります。

委任予算は増援の生産に使います。利用できる生産施設があり、予算内に収まる兵種から不足するものを発注します。完成部隊は自動的にその将軍へ所属します。建設と全軍の維持費は従来どおり陣営の手元資金で扱います。委任予算を超えて発注することはありません。

発注を生産メニューで取り消すと、代金は発注元の将軍の予算へ戻ります。生産施設が破壊された予約の代金は戻りません。「部隊の指揮を返還」で直属へ戻せます。通常の移動・停止・地点攻撃などを直接命令した部隊も、その将軍から外れます。予算の返還と部隊の返還は別操作です。

部隊の返還は現存部隊が対象です。発注済み増援の所属はそのままなので、増援も止める場合は生産予約を取り消してください。従来のZキーによる汎用AIへの委任も残しています。人物ごとの地域・予算・特性を使う委任は司令部から設定します。

## 将軍からの提案

将軍は開始からシミュレーション時間5秒後に初回の提案を出し、その後は90秒ごとに見直します。提案が届くと通知され、司令部ボタンに未回答の件数が表示されます。各将軍の「将軍からの提案」で希望戦地・追加予算・理由を確認できます。同じ希望のままであれば通知を繰り返しません。訓練中は既存の課題に集中できるよう、自発的な提案は停止します。

希望戦地は、自軍と公開されている都市の支配、視認済みの敵、現在の担当部隊からの距離、他の将軍の担当、特性を使って選びます。兵力温存・守備重視は味方拠点、機動襲撃は価値の高い敵拠点、補給重視は補給の通った味方拠点を好みます。未確認の敵部隊は判断に使いません。

希望予算は、特性や現在の指示に応じた編成と、担当部隊・発注済み増援・未使用予算の不足から計算します。機甲集中は戦車とIFV、火力優先は砲兵とロケット、偵察重視は偵察機とFPV班を求めます。手元資金より大きい希望を出す場合もあります。

- **予算を承認**：不足分を将軍の委任予算に移します。承認直前に再計算し、手動配分や予約済み増援との重複を防ぎます。
- **戦地を承認**：希望する担当円に変更します。部隊の所属と指示はそのままです。予算だけ・戦地だけの承認も可能です。
- **両方を承認**：予算と戦地をまとめて承認します。資金が不足する場合は両方とも変更しません。
- **地図で見る**：希望する戦地を破線で確認できます。未承認の提案によって実際の担当は変わりません。
- **見送る**：提案を閉じ、最低90秒は再提案を控えます。その後の定期見直しで必要なら再提案します。

承認されるまで、将軍が提案だけを理由に予算を引き出したり、担当領域や部隊の所属を変えたりすることはありません。

## 地図で担当を確認する

「担当領域 ON / OFF」で表示を切り替えます。将軍ごとに固定の色と1～9の番号を使い、薄い塗りと境界で担当円を表示します。地図上は**肖像画像・番号・名前・現在の指示・担当部隊数をまとめたカード**で表示し、重なりそうなカードはずらして線で担当中心と結びます。カードを押すとその将軍の司令部を開けます。担当領域は重複することがあります。

所属部隊の輪、ミニマップの担当円・中心、画面右のカード一覧も同じ色です。右のカードにも肖像・名前・指示・部隊数を表示し、押すとその将軍の担当領域へ移動して司令部を開きます。小さい画面では「前の担当」「次の担当」で一覧を切り替えられます。地域を指定済みの将軍は、予算や部隊がまだ0でも表示します。敵側の担当領域・所属は表示しません。

希望戦地のプレビューは破線と「希望」の表示で区別します。「提案へ戻る」から承認・見送りへ戻れます。

## 指示

| 指示 | 判断 |
| --- | --- |
| 積極攻勢 | 攻勢に必要とする優勢の基準を緩め、担当内の敵都市・確認目標へ進む |
| 全力防御 | 敵地への進出を控え、自軍地域へ侵入した確認敵に対応する |
| 臨機応変 | 戦力差、耐久、補給を見て攻守を選ぶ |

## 将軍の特性

両陣営で同じ特性体系を使います。特性は損害倍率などの隠れた強化ではなく、判断と増援編成に反映します。実際の戦果と損失は盤面によって変わります。

| 特性 | 判断・編成 |
| --- | --- |
| 突破重視 | 不利でも攻めやすく、撤退は遅い。損失が増えやすい |
| 兵力温存 | 大きな優勢を確認して前進し、早めに撤退する |
| 均衡調整 | 中程度の優勢を目安に攻守を切り替える |
| 機甲集中 | 戦車とIFVを優先して増援。予算負担は大きい |
| 火力優先 | 砲兵・ロケット砲・偵察を優先し、支援部隊の後退距離を大きくする |
| 偵察重視 | 地域内に偵察機が入るまで攻勢を控える |
| 守備重視 | 臨機応変でも守備を選びやすい。積極攻勢を明示すれば攻める |
| 機動襲撃 | IFVとドローンを好み、都市の価値を目標選定へ反映する |
| 補給重視 | 地域の補給切れが多い間は進撃を控える |

## 参謀本部

「助言と戦力案」では、将軍に未委任の自軍戦力、直属用の発注済み部隊、確認できる敵装甲・航空戦力、補給切れ、砲弾在庫を基に編成を提案します。敵の未確認部隊は数えません。劣勢な戦線が見つかれば予備隊投入と防御指示を助言します。

「戦力案を発注（可能な分）」を押すと、手元資金と生産施設が許す範囲だけ発注します。将軍の委任予算は使いません。この操作で完成する部隊は直接指揮になります。発注できなかった不足は次の戦力案に残ります。

「戦線レポート」は北部・中央・南部の3戦線を対象に、**シミュレーション時間60秒ごと**に生成します。自軍部隊、確認敵、補給切れ、前回報告からの確認戦果・自軍損失を記録します。ゲーム速度の変更や一時停止に従います。直近6回分（3戦線×6回＝18件）を参謀本部で読み返せます。

セーブ形式5に委任予算、部隊、担当円、明示的な地域割当、指示、発注者、報告、未回答の提案と再提案の待ち時間を保存します。従来の形式3・4も読み込めます。

## 検証

`cargo test --release -p yydrone-core -- --skip long_sim_finishes_with_winner`、`cargo test --release -p yydrone-game`。将軍への割り当て、予算の分離・返金、増援の所属、指示と特性による命令差、霧による情報制限、9将軍の保存・読込、旧形式3との互換、小画面での操作範囲を検証します。将軍9人へ委任した状態で進める戦役テストも含みます。

WebAssembly版をビルドして `dist/yydrone.wasm` を更新した後、インストール済みChromiumがある環境では `node tools/verify_command_ui.mjs` で実ブラウザの操作と描画を確認できます。専用の隔離プロファイルを `target/` に作り、通常のブラウザ設定や記録は使用しません。

確認した画面：[将軍への指示・予算](command-ui-generals.png)、[担当円と部隊](command-ui-region.png)、[参謀の戦力案](command-ui-staff-plan.png)、[定期報告](command-ui-periodic-report.png)、[小画面の参謀本部](command-ui-compact-staff.png)。

`node tools/verify_command_ui.mjs <chrome.exeのパス> --proposals` では、自発的な提案通知、予算と戦地の承認、希望戦地のプレビュー、9人の担当表示・切替・一覧からの司令部移動を、デスクトップと1000×480の両方で確認します。
